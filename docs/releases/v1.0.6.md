# TypeCraft v1.0.6 — Startup and typing performance

TypeCraft is a local-first Markdown editor for focused writing: plain files, a browser-based interface, and no account required.

## What's new

- **Faster startup**: the fixed 200ms delay before launching the browser is gone — the loopback server is bound before the browser is even started, so the sleep was pure latency. On systems with no Chromium-family browser installed (plain Fedora with Firefox), the `xdg-settings` query is skipped entirely: its only purpose is to order Chromium-family candidates, and a cheap PATH scan now decides whether it is worth a process launch at all. Measured server startup: ~13–50ms from exec to HTTP ready.
- **Smoother typing on large documents** — every per-keystroke path was reduced from "walk the whole document" to "touch only what changed":
  - The typewriter caret mirror caches the first-row position of the current line and re-measures only the line slice while you type inside it (O(line) layout instead of O(document)); a conservative reuse rule falls back to the full mirror on line changes, jumps, or anything it cannot prove.
  - The focus-dim backdrop keeps three persistent spans and updates only the current sentence/paragraph with `textContent` — no more escaping and re-parsing the entire document's HTML on every keystroke.
  - Word/character/sentence statistics are debounced (250ms): they ran four whole-file regexes per keystroke just to update a status bar nobody reads while typing.
  - The cursor position is computed with native index scans instead of copying and splitting the whole text prefix.
  - Above 150KB, the outline and preview reparse debounces slow from 120/150ms to 400ms, so bursts of typing never queue a full parse per keystroke.
- **Behaviour is unchanged**: the focus-range tokenizer, the typewriter centring target and all the document-session safety properties are identical; the two new hot-path regression tests (152 frontend tests in total) pin the incremental render and the mirror-cache reuse rule to the previous observable behaviour.

## Download and install

Download the package for your system in [Release assets](https://github.com/massigent/typecraft/releases/tag/v1.0.6) or in the [download folder](https://github.com/massigent/typecraft/tree/downloads/v1.0.6). Use `SHA256SUMS` to verify the file.

| Platform | File | Command from the download directory |
| --- | --- | --- |
| Ubuntu | `typecraft_1.0.6-1_amd64.deb` | `sudo apt install ./typecraft_1.0.6-1_amd64.deb` |
| Fedora | `typecraft-1.0.6-1.x86_64.rpm` | `sudo dnf install ./typecraft-1.0.6-1.x86_64.rpm` |
| Linux, portable | `TypeCraft-x86_64.AppImage` | `chmod +x TypeCraft-x86_64.AppImage && ./TypeCraft-x86_64.AppImage` |
| Windows x64 | `TypeCraft-1.0.6-windows-x64-setup.exe` | Run the installer; open TypeCraft from the Start menu |
| macOS, Apple Silicon (M-series) | `TypeCraft-1.0.6-macos-arm64.zip` | Extract the ZIP and drag `TypeCraft.app` to Applications |
| macOS, Intel | `TypeCraft-1.0.6-macos-amd64.zip` | Extract the ZIP and drag `TypeCraft.app` to Applications |

Without FUSE, use `APPIMAGE_EXTRACT_AND_RUN=1 ./TypeCraft-x86_64.AppImage`. The Linux packages were built and smoke-tested on Linux. Full installation on Fedora and AppImage launch through FUSE were not tested on the build host.

The Windows and macOS packages were cross-built and their payloads verified on Linux, not installed or run on native systems. The Windows installer is not Authenticode-signed. The macOS app has no Developer ID signature and is not notarized. Windows SmartScreen or macOS Gatekeeper may warn or block launch.

To check one download against the manifest, run `sha256sum --ignore-missing -c SHA256SUMS` in the download directory.
