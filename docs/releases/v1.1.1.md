# Rigo v1.1.1 — Upgrades keep your preferences

Rigo is a local-first Markdown editor for focused writing: plain files, a browser-based interface, and no account required.

**One fix in this release:** upgrading from the previous name (TypeCraft) no longer resets the editor preferences. The recents list was already carried over; the theme, font, view mode, typewriter, focus and sound settings were not.

## What was wrong

The preferences live in the browser profile's localStorage (`~/.rigo/browser-profile`). On the rename, v1.1.0 recreated the profile from scratch instead of carrying the old one over (`~/.typecraft/browser-profile`), so:

- the one-time localStorage migration could never fire — it reads the *new* profile, which never contained the old `typecraft.*` keys;
- the app started with the defaults, which also changed look with the new bundled fonts.

## The fix

On first start, if `~/.rigo/browser-profile` does not exist and the old one does, the profile directory is carried over with an atomic rename — the same one-shot, failure-tolerant policy already used for the recents list. The existing in-browser migration then maps the old theme and font identifiers (`ia-light` → `light`, `ia-mono` → `plex-mono`, …) to their replacements. Nothing is touched if the new profile already exists, and a fresh installation is unaffected.

Two regression tests cover the carry-over, its idempotency (a second run can never damage the migrated profile), and the no-legacy no-op.

## If you already ran v1.1.0

Your preferences were already reset when v1.1.0 created the new profile, and v1.1.1 cannot bring them back (it only migrates when the new profile is absent). If the old directory is still on disk, close Rigo and restore it by hand:

```sh
rm -rf ~/.rigo/browser-profile
mv ~/.typecraft/browser-profile ~/.rigo/browser-profile
```

On the next start the old theme, font, typewriter, focus and sound settings come back with their new names.
